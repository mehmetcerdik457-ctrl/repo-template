# Security Policy

## Reporting a vulnerability
Do not publish exploitable details in a public issue.

Use the repository Security tab and private vulnerability reporting when available. If private reporting is unavailable, contact the repository owner privately through the GitHub profile contact method.

## Security rules
- Never commit API keys, tokens, passwords, private keys, keystores, recovery codes, signing material, or production credentials.
- Rotate credentials immediately if exposure is suspected.
- Review dependency, workflow, release, model, container, and generated-artifact changes as supply-chain changes.
- Security-sensitive changes require reproducible verification evidence.
